# JS Control 0.2 — экспериментальное подключение всего соца

## Установка / обновление

Распакуйте ZIP. Если обновляете 0.1, скопируйте новые файлы в прежнюю папку
extension и нажмите ↻ «Обновить» на карточке расширения в chrome://extensions.
При новой установке: режим разработчика → загрузить распакованное расширение
→ папка с manifest.json. Перезагрузите Ads Manager после обновления.

## Первая проверка

1. В нужном браузерном профиле откройте Ads Manager и дождитесь загрузки.
2. Откройте JS Control. Если нужно, активируйте демонстрационный ключ:
   js_demo_K7mQ2vN8xR4pT9cW6aY3
3. Нажмите «Подключить соц». Разрешите доступ только к graph.facebook.com.
4. Расширение попробует прочитать ID пользователя и уже загруженный локальный
   API-доступ из Ads Manager. Это экспериментальный адаптер: названия
   внутренних модулей Meta могут измениться, данные могут быть недоступны.
5. При успехе появятся FB-соц и список доступных через этот доступ кабинетов.
   Связанные БМ получаются из этих кабинетов: это не полный список всех БМ.
6. Выберите даты → «Обновить весь соц». Каждый кабинет собирается последовательно;
   отдельные вкладки и ручное подключение каждого кабинета не нужны.
7. Отправьте скрин результата и экспорт JSON. Если подключение не удалось,
   пришлите сообщение статуса и раздел «Диагностика».

## Данные и безопасность

Подключение read-only: изменение рекламы не реализовано. Прокси/fingerprint
не меняются. Cookies не считываются и не передаются.
API-доступ хранится в chrome.storage.session только в доверенном контексте
расширения, до закрытия браузера. В JSON и статусах его нет. Нет backend
и отправки наших данных Dolphin/CRM. Запросы с локальным токеном идут
непосредственно в Meta. Подписка — локальная демонстрация, а не коммерческая
авторизация. Лимит — один соц, до 100 найденных кабинетов в этом прототипе.

Соц проверяется через /me и сравнивается с ID страницы до сохранения.
Сбор списка использует /USER_ID/adaccounts с пагинацией.
Кабинеты ограничены реальными разрешениями токена; это не подтверждение
доступа ко всем активам пользователя через любой другой канал.
Статистика каждого кабинета сохраняет валюту и часовой пояс; валюты не
суммируются. Даты интерпретируются в часовом поясе кабинета.

После закрытия браузера для восстановления локального доступа нужно снова
нажать «Подключить соц» в Ads Manager. Постоянное подключение профиля и
автоматическое восстановление в следующих версиях ещё не реализованы.

Очередь сбора сохраняется локально. При приостановке service worker она
продолжается через chrome.alarms; при ошибке авторизации/лимите Meta сбор
останавливается. Повторный запуск одного read-only кабинета безопасен:
последний снимок заменяется, накопительный spend не прибавляется к старому.
Ошибки отдельных кабинетов отображаются отдельно; прежний успешный снимок
может остаться с прежними датой и временем. Нажмите «Остановить», чтобы
отменить дальнейший сбор. Уже выполняющийся read-only запрос может завершиться.

Проверки на фикстурах не заменяют живую проверку в FB.
Node.js 22+: node --test extension/tests/*.test.mjs

### 0.2.1
Адаптер дополнительно проверяет AdsAPIConfig и экранированные поля конфигурации в уже загруженных скриптах. Это экспериментальный fallback, его наличие в конкретной живой сессии проверяется при подключении. Диагностика содержит только доступность модулей и счетчики, без токенов.

### 0.2.2 — запросы выбранной вкладки
Если доступ не найден в конфигурации страницы, «Подключить соц» включает наблюдение на 5 минут. Закройте popup, перезагрузите ту же вкладку Ads Manager, дождитесь загрузки и нажмите подключение снова.
Расширение использует webRequest с разрешением на Graph API и сайты-инициаторы Facebook. После явного подключения обрабатываются только запросы выбранного tabId к graph.facebook.com от исходного домена вкладки. Читается только поле access_token в URL или formData; cookies, заголовки, raw-тело и другие поля не читаются. Запросы не меняются. Кандидаты остаются в storage.session, не попадают в экспорт/логи и проверяются через /me на соответствие владельцу. Наблюдение завершается через 5 минут или после подключения/отключения.
Если Ads Manager не использует Graph-запросы с этим полем, способ тоже не сработает. Это экспериментальная сборка для проверки живой сессии, не подтвержденная интеграция.
Документация Chrome: https://developer.chrome.com/docs/extensions/reference/api/webRequest

### 0.2.3 — локальный импорт токена соца
Откройте Ads Manager нужного соца. В секции «Подключить через токен Facebook / FBacc» вставьте принадлежащий вам пользовательский токен с доступом к рекламе. Расширение проверит /me на соответствие ID открытой сессии и получит все доступные этому токену кабинеты. Наличие ads_read и работоспособность стороннего токена не гарантируются: проверяются реальные ответы Meta. Токен не отправляется в CRM или FBacc, только в Graph API; хранится в защищенной storage.session, не попадает в STATE/экспорт/диагностику. Это ручной резервный способ, не автоматическая интеграция с FBacc и не решение автоматического извлечения.

### 0.2.4 — диагностика отказа подключения
Ошибка подключения теперь содержит этап identity (/me) или adaccounts (список кабинетов), HTTP-статус, код/подкод, признак временной ошибки и ограниченную категорию причины. Сырой текст ответа, trace ID и токен не сохраняются. Эта версия уточняет причину отказа; сама по себе не исправляет отказ Meta.

### 0.2.5 — очищенное сообщение ошибки
Диагностика подключения добавляет failure.detail с сообщением Meta, после удаления переданного токена, строк EA…, URL, email, длинных идентификаторов и числовых ID. Сырой ответ и trace ID не сохраняются. Это уточнение причины отказа, не исправление ошибки доступа.

### 0.2.6 — альтернативный формат запроса
При точном ответе code=1, message="Invalid request.", is_transient!=true выполняется одна попытка через пакетный Graph API: POST на корень API с access_token в теле и единственным вложенным GET. Записи рекламы нет, токен не добавляется в URL. Успешный транспорт запоминается в памяти worker для следующих чтений; отключение очищает кеш. Сбой прав/лимитов/истечения не повторяется. Это проверяемая гипотеза совместимости токена FBacc, не подтвержденная причина его отказа.
