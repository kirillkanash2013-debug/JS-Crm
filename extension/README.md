# JS Control — автономный прототип 0.1

Один кабинет, локальное хранение, демонстрационная активация, сбор страницы,
опциональный полный сбор через разрешённый Meta Marketing API, экспорт JSON.

## Установка и первая проверка

1. Скачайте артефакт **JS-Control-0.1.0** из workflow **JS Control extension checks**.
   Распакуйте ZIP. В полученной папке рядом должны лежать manifest.json и panel.html.
   Альтернатива: скачайте ZIP ветки claude-code и используйте папку extension внутри.
2. В нужном браузерном профиле откройте chrome://extensions.
3. Включите «Режим разработчика» → «Загрузить распакованное расширение».
   Выберите папку с manifest.json. Закрепите значок JS Control на панели браузера.
4. Откройте Facebook Ads Manager, выберите один рекламный кабинет.
   В адресе страницы должен быть параметр act=ЧИСЛОВОЙ_ID.
5. Нажмите значок расширения → «Вставить демонстрационный ключ» → «Активировать».
6. Нажмите «Подключить текущую вкладку», затем «Снять данные страницы».
7. Проверьте ID кабинета, загруженные строки и статусы диагностики.
   Экспортируйте JSON для проверки. Файл не содержит токенов и cookies,
   но содержит названия и данные рекламы — не публикуйте его.

Демонстрационный ключ: js_demo_K7mQ2vN8xR4pT9cW6aY3

## Что означает демонстрационная подписка

Ключ проверяется локально. Это демонстрация UX активации, а не платёжная система
и не защита коммерческой подписки. Срок, удалённый отзыв, пользователи и лимиты
на сервере ещё не реализованы. Ключ не предоставляет разрешения Facebook.
Без внешнего сервера расширение не отправляет данные нашей CRM или Dolphin.

## Два разных режима

**Страница**: расширение по вашему нажатию читает видимые таблицы Ads Manager.
Это только строки, загруженные в DOM. Прокрутка, фильтры и переключение кабинета
влияют на результат. Если таблицы не распознаны, результат содержит 0 строк:
это не означает отсутствие кампаний. Авторизация Facebook, период и валюта
не верифицируются. Нормализованные кампании появляются только при наличии
явных колонок Campaign ID/ID кампании и Campaign/Кампания.
Spend и бюджеты страницы хранятся как исходный текст, без догадок о валюте
и периоде. Снимок помечен complete:false.

**Meta API**: нужен уже выданный разрешённый токен с доступом к кабинету.
Введите его только в поле расширения, не в чат. На кнопке «Подключить API»
Chrome попросит разрешение только для graph.facebook.com.
Выберите даты в часовом поясе кабинета и нажмите «Собрать через API».
Сбор получает метаданные кабинета, доступные кампании и дневной spend,
проходит пагинацию, проверяет кабинет, дату, валюту и дубликаты.
Снимок complete:true означает успешное получение всех страниц выбранных API
запросов, а не всех архивных/удалённых объектов за всю историю Facebook.
Нет преобразования валюты. Настроена версия API v25.0.

Токен хранится в chrome.storage.session, доступной только доверенным контекстам
расширения, до закрытия браузера. Он не попадает в экспорт, URL запросов и логи.
После нового запуска браузера автообновление выключено; нужно подключить
токен заново. При любой ошибке API автообновление также выключается.
Если настройки вашего Meta app требуют appsecret_proof, этот прототип
не подходит: секрет приложения не должен храниться в расширении.

## Границы версии 0.1

- Один кабинет; смена кабинета очищает прежний снимок и токен.
- Нет регистрации в нашей CRM, backend, платежей и реального отзыва ключей.
- Нет извлечения токенов из сессии Facebook или передачи cookies.
- Нет перехвата запросов, изменения proxy/fingerprint или новых входов в FB.
- Нет чтения всех БМ/соцов, сбора адсетов и объявлений.
- Нет изменения бюджетов, включения/выключения рекламы.
- Автообновление раз в час работает только для успешно проверенного API-режима,
  пока запущен профиль браузера. Страница сама не перезагружается.
- Локально хранится только последний снимок, предыдущий заменяется после успеха.
- При ошибке последний успешный снимок остаётся с исходным временем.
- Живая проверка на Facebook нужна: тесты репозитория используют имитацию API.

## Подключение к CRM позже

Схема JSON v1 разделяет account, campaigns, metrics, observedAt, period и
complete. Для будущего адаптера: не суммировать повторные накопительные
снимки; неполные снимки не заменяют полную базу. Всегда учитывать валюту
и часовой пояс кабинета. Поставщика подписок заменить в core.mjs; реальную
авторизацию и ограничения проверять сервером для каждой операции.
