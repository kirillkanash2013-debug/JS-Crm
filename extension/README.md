# JS Control 0.7.0 — простое подключение для клиента

Главный экран переделан под клиента. Технические инструменты убраны
в свёрнутый раздел «Для администратора и диагностики».

Как подключиться:
1. **Вход.** Ввести один ключ доступа `js_srv_…`. Расширение сразу проверяет его на сервере
   и сохраняет. Вводить ключ при каждом открытии больше не нужно. Демо-ключ работает
   через ссылку «Попробовать демо-режим» (сбор только при открытом браузере).
2. **Ads Manager.** Расширение само находит открытую вкладку Ads Manager.
   Если вкладки нет, кнопка «Открыть Ads Manager» откроет её.
3. **Подключить соц.** Подтвердить передачу сессии серверу, при необходимости указать прокси
   и нажать одну кнопку. Расширение проверит соц. Если доступ ещё не виден, оно само
   перезагрузит Ads Manager и повторит попытку. Затем передаст сессию на сервер, запустит
   первый сбор и включит обновление каждые 15 минут.

После подключения вместо JSON показывается карточка статуса. В ней: состояние понятным
текстом (работает / идёт сбор / сессия истекла), соц, число кабинетов, время последнего
сбора, кампании, группы и объявления, spend по валютам, время следующего обновления.
Есть кнопки «Обновить сейчас», «Переподключить соц» (появляется, когда сессия истекла)
и «Отключить соц». Если сервер не удалил сессию, соц остаётся подключённым и отключение
можно повторить. Ошибки сервера показываются понятным текстом, а не как HTTP-коды.

Генерация ключа владельца, адрес сервера, ручные кнопки сервера, тестовая кампания,
импорт токена, recorder и таблицы остались без изменений в разделе администратора.
Сервер (Cloudflare collector) не менялся. Персональный ключ по-прежнему один на владельца:
чтобы выдавать отдельные ключи клиентам, нужна поддержка нескольких клиентов на сервере.

## 0.6.0: серверная автономность

Добавлено отдельное подключение к автономному серверу. Раскройте «Автономный сервер»: HTTPS-домен, персональный серверный ключ, необязательный прокси, согласие на передачу сессии. Обычное «Подключить соц» по-прежнему проверяет только локальный доступ. Реальная автономность требует развёрнутого сервера из `server/README.md` и живой проверки после закрытия браузера. Демо-ключ не является серверным ключом. Cookies запрашиваются как дополнительное разрешение только при серверном подключении; обычный экспорт их не содержит. Доступ к произвольному HTTPS-серверу объявлен дополнительным разрешением, выдаётся только выбранному адресу.

# JS Control 0.5.1

Локальное расширение: один Facebook-соц, до 100 доступных кабинетов,
кампании и расходы за выбранный период (до 31 дня). Подключение только для чтения.

## Установка и проверка

1. Скопируйте содержимое папки extension из нового архива в установленную папку.
2. Нажмите «Обновить» на карточке JS Control в chrome://extensions.
3. Откройте Ads Manager в нужном профиле, перезагрузите страницу, дождитесь загрузки.
4. Откройте JS Control и нажмите «Подключить соц».
   Если нужна активация: js_demo_K7mQ2vN8xR4pT9cW6aY3.
5. Если FBacc уже открыт, расширение может использовать его локальный доступ.
   Для работы без FBacc оно также ищет доступ в загруженных скриптах Ads Manager.
6. После подключения нажмите «Обновить весь соц». Привязывать каждый кабинет не нужно.

## Что изменилось

Раньше запросы шли из фонового процесса с Bearer-заголовком без браузерной сессии.
В 0.3.0 подключение и сбор всего соца используют XHR из MAIN-контекста выбранной
вкладки Ads Manager, withCredentials=true и access_token в запросе Graph API.
Это воспроизводит обнаруженный механизм транспорта FBacc; его сторонний код
не включён в расширение. API остаётся v25.0, устаревшая v19.0 не копируется.
Пакетный fallback для этого пути отключён.

Вкладку Ads Manager нужно держать открытой во время сбора. Перед каждым
запросом проверяются домен страницы и ID текущего пользователя. Смена соца,
закрытие вкладки, окончание сессии или изменение внутренних модулей Meta
могут остановить чтение. После перезапуска браузера нужно подключить соц снова.

Прокси, если он уже настроен в профиле браузера, используется этим профилем.
Отдельного прокси или сервера в этой версии нет. Cookies используются браузером
для запросов Meta, но расширение не читает и не экспортирует их. Токен хранится
в доверенном chrome.storage.session до закрытия браузера и передаётся локально
в выбранную вкладку для запроса Meta. Он не включается в экспорт или диагностику.
Он присутствует в URL запроса Meta, как у FBacc, поэтому не пересылайте HAR
или сырые скриншоты Network с адресами запросов.

Список кабинетов ограничен разрешениями доступа Meta. Связанные БМ получаются
из найденных кабинетов: это не полный независимый список всех БМ. Валюты
сохраняются отдельно, расходы разных валют не складываются. При ошибке
кабинета сохраняется прежний снимок с прежней датой. Ошибки авторизации
и лимитов останавливают сбор. Нет отправки данных в Dolphin или CRM,
изменения рекламы, настоящего биллинга подписки или автономной работы
при закрытом браузере. Старые кнопки API/видимой таблицы не являются новым
сценарием подключения всего соца.

## Запись запросов Meta — 0.4.0

Подключение 0.3.0 сохранено. Добавлена отдельная запись запросов одной
выбранной вкладки через webRequest: Graph API и Facebook GraphQL/ads AJAX.
Нажмите «Начать запись» в Ads Manager, разрешите доступ к сайтам Facebook,
закройте окно расширения и работайте в этой вкладке. Перезагрузка вкладки
не сбрасывает запись. Она останавливается через 15 минут или после 300 записей.
Можно остановить её раньше и нажать «Экспорт записи».

Для проверки:
1. Начните запись в тестовом кабинете и перезагрузите Ads Manager.
2. Откройте по очереди «Кампании», «Группы объявлений», «Объявления».
3. Измените период отчёта и дождитесь обновления расхода.
4. На отдельной тестовой кампании измените статус на PAUSED.
   Если она уже приостановлена, не включайте её ради теста, если не готовы
   к запуску рекламы. Для исследования включения используйте кампанию,
   которую действительно разрешено запустить, и восстановите исходный статус.
5. При необходимости измените бюджет только тестовой кампании/группы
   и сразу верните прежнее значение. Опубликованные изменения могут влиять
   на расходы; для записи чтения эти действия не требуются.
6. Остановите запись, экспортируйте JSON и передайте его для анализа.

Сохраняются нормализованный путь (без ID), операция из разрешённых семейств,
doc_id, метод, время, HTTP-статус, длительность, разрешённые имена полей,
распознанные числовые daily/lifetime budgets и перечислимые статусы.
Токены, cookies, заголовки, полные URL, имена кампаний, ID рекламных объектов,
сырые тела и ответы не сохраняются. Сырые POST-данные разбираются локально
только до 256 KiB, затем отбрасываются. Значения бюджетов в API могут быть
в минимальных единицах валюты — это не сумма для отображения пользователю.

Это карта наблюдаемых запросов, а не полные повторяемые шаблоны. Некоторые
форматы тела или названия операций могут не распознаться; HTTP 200 не
доказывает успешную мутацию GraphQL. Запись не выполняет запросы, не меняет
рекламу и не доказывает доступ к управлению. Не охватывает другие вкладки,
запросы до запуска записи или весь возможный функционал Dolphin.
Экспорт не отправляется автоматически. Очистка/отключение соца удаляют журнал.
31 автоматическая проверка на фикстурах; живая запись ещё требует проверки.

## Исправления рекордера — 0.4.1

Убран фильтр только Ads/Biz/Comet-операций. Название из служебного поля
сохраняется для любого безопасного ASCII-имени; токены/секреты отбрасываются.
Добавлены корневые пакетные запросы Graph API, вложенные JSON-строки,
массивы и camelCase-поля бюджетов/статусов. Сохраняется ограниченная схема
полей (путь и тип без произвольных значений) для анализа неизвестных форматов.
Бюджеты внутри объектов amount/value распознаются только в контексте бюджета.
ID объектов и полные relative_url пакетных запросов не сохраняются.

Экспорт schemaVersion=2 добавляет operations/docIds, batchMethods, shape,
changeCandidates, truncated и kind. mutation-candidate означает лишь наличие
операции с суффиксом Mutation, а не доказательство успешного изменения.
HTTP 200 всё ещё не подтверждает успех GraphQL, ответы не записываются.
Ключи структуры фильтруются, секретные поддеревья целиком пропускаются.
Ограничения разбора: глубина 8, до 1500 узлов, 150 полей/элементов схемы,
60 кандидатов изменений. При ограничении выставляется truncated.

34 проверки на фикстурах. Подключение и транспорт сбора не менялись.
Для повторной проверки достаточно короткой записи: открыть окно бюджета
или статуса, а если нужна фиксация мутации — выполнить и опубликовать изменение
только на подходящем тестовом объекте и восстановить исходное значение.
Проверка подключения заново и повтор всей навигации не обязательны.

## Охват записи — 0.4.2

После подтверждения пользователем публикации изменения журнал 0.4.1 всё ещё
содержал только Query. Это не означает отсутствие изменения в Facebook.
Обнаружено ограничение рекордера: только четыре домена и перечень путей.

Новый recorder слушает https://*.facebook.com/*, включая возможные служебные
поддомены, но по-прежнему только выбранный tabId. Кнопка записи запрашивает
расширенное разрешение отдельно. Подключение и сбор данных не изменены.
Graph/adsmanager-graph и GraphQL/ads AJAX разбираются в безопасную схему.
Остальные Facebook XHR/fetch/POST сохраняются только как метаданные:
домен, маскированный путь, тип, метод, время и HTTP-код. Их тело не читается.
Это позволяет видеть неизвестный маршрут вместо молчаливого пропуска.
Части пути вне фиксированного словаря заменяются :segment, ID — :id.
Неизвестные адреса отражаются отдельным счётчиком.

36 проверок на фикстурах. Точный маршрут живой публикации ещё не установлен.
Новую короткую запись начинайте непосредственно перед публикацией тестового
изменения. Подтвердите дополнительное разрешение браузера. Запросы других
вкладок и tabId=-1 не включаются: этот охват явно ограничен выбранной вкладкой.
Записи не подтверждают успешность мутации, ответы GraphQL не считываются.

## 0.5.0 — структура и найденный формат редактирования

Кнопка «Собрать структуру» проходит по всем подключённым кабинетам через
ту же сохраняемую очередь, что и статистика. Читает campaigns, adsets, ads,
проверяет account_id, уникальность ID и родительские связи. Сохраняет только
проверенный полный результат кабинета; при ошибке остаётся прежний снимок.
Это полная структура доступных токену рекламных объектов, а не обещание
доступа ко всем БМ, страницам, креативам, платежам и истории Facebook.
Подключение использует подтверждённый пользователем транспорт 0.3.0.

В таблице структуры отображаются первые 100 объектов; экспорт содержит все.
Бюджеты в структуре сохраняются в API-единицах без самовольного перевода
в валюту. «Обновить весь соц» отдельно собирает кампании и spend по дням.
Статистика и структура имеют самостоятельное время снимка; не считаются
атомарным состоянием Meta. Отмена, лимиты, истечение сессии учитываются.

Recorder дополнительно распознаёт наблюдавшийся формат values[]:
field / old_value / new_value для разрешённых бюджетов и статусов.
Сохраняет прежнее и новое значение; произвольные тексты и секреты не берёт.
Graph-пути версии/:id/служебная_операция сохраняют безопасное имя операции,
ID остаётся скрытым. _reqName учитывается; lowercase method нормализуется.
Эти признаки обозначают кандидата изменения, не успешную публикацию.

40 автоматических проверок на фикстурах. Новый сбор структуры и разбор
изменений ещё не подтверждены в живом Facebook. Управление рекламой,
повтор запросов, Cloudflare/CRM/TG-передача в эту версию не включены.
Сырые тела, cookies и токены не экспортируются. Технические изменения
не дают доступа к закрытой серверной реализации Dolphin.
