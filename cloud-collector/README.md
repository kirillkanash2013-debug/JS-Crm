# Cloudflare: JS Control 0.6.1

Отдельный Worker `js-control-collector-claude`. Telegram workers не меняются. Linux/Chromium работает в Cloudflare Container; внешний VPS, отдельный домен, R2 и S3-ключи не нужны. HTTPS предоставляется на workers.dev.

## Хранение и автономность

- Сессия и результаты зашифрованы AES-256-GCM в Durable Object. Данные разбиваются на части 64 KB и записываются транзакцией. Диск контейнера для постоянного хранения не используется.
- Durable Object Alarm запускает работу без открытых вкладок/компьютера. Очередь и расписание сохраняются при остановке контейнера и выгрузке Worker.
- Контейнер принимает только внутренние запросы с отдельным секретом. Public Worker допускает только известные `/v1/*` операции и проверяет персональный ключ до запуска контейнера.
- Задание имеет lease/attempt и ревизию сессии. Повтор после падения безопасен для чтения; результаты отменённых или заменённых подключений не публикуются.
- Прототип допускает один соц и один одновременно работающий контейнер. Пользовательский proxy HTTP/SOCKS5 передаётся в Chromium после проверки публичного IPv4 и фиксации DNS.
- Когда сбор не выполняется, контейнер выключается после минуты простоя. При активном сборе он остаётся включённым. Максимум работы браузера — 13 минут, lease задания — 15 минут.

## Деплой

Workflow `.github/workflows/cloud-collector.yml` запускается при push в `claude-code`. Он использует уже существующие `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` GitHub secrets, проверяет код, собирает Docker и выкатывает сервис. Токен должен иметь права на Workers/Containers/Durable Objects и Registry, необходимые Wrangler. При недостаточных правах workflow остановится; это не является успешным деплоем.

После деплоя `bootstrap-secrets.mjs` создаёт `VAULT_KEY` и `INTERNAL_KEY` напрямую в Cloudflare. После этого выполняется защищённая проверка реального Chromium в Cloudflare (`source: cloudflare-browser-smoke`, `facebookVerified: false`). Отдельный DEPLOY_SMOKE_KEY меняется на каждом деплое; VAULT_KEY и INTERNAL_KEY не меняются. Значения не выводятся в логи и не кладутся в репозиторий/артефакты. Существующие ключи никогда автоматически не заменяются. Сохраните ключ шифрования в своём защищённом административном процессе; его потеря или ручная замена сделает сохранённые сессии недоступными.

## Однократное подключение владельца

1. Проверить `https://js-control-collector-claude.kirill-kanash2013.workers.dev/health`. Ответ `ok` подтверждает шлюз, не Facebook.
2. Установить расширение 0.6.1. Открыть «Автономный сервер», нажать «Создать персональный ключ». Ключ генерируется на компьютере владельца, сохраняйте его у себя. Повторное нажатие создаёт новый ключ, а не восстанавливает старый.
3. В Cloudflare открыть Workers & Pages → `js-control-collector-claude` → Settings → Variables and Secrets → Add. Тип **Secret**, имя **JS_CONTROL_OWNER_KEY**, значение — созданный `js_srv_…` ключ. Сохранить/Deploy.
4. Вернуться к расширению: тот же ключ, адрес сервера уже заполнен. В выбранном профиле Ads Manager подключить соц, указать его прокси, подтвердить передачу сессии и нажать «Передать подключение».
5. «Собрать на сервере» → «Проверить результат». Только `done` + `source: facebook-server` + `complete: true` подтверждают полный сбор. Сохранение подключения возвращает `unverified`.
6. Включить расписание, закрыть браузер. Позже проверить `startedAt` и `observedAt`: должны быть позже закрытия. Сравнить фактические данные с Ads Manager. Период расписания — текущая дата UTC; CRM может передавать свой диапазон через jobs API.

Персональный ключ не связан с публичным `js_demo_…` ключом расширения. Шлюз закрыт, пока Cloudflare Secret `JS_CONTROL_OWNER_KEY` не настроен. Cookies/пароль прокси не отправлять в чат или GitHub. Для клиентов продукта потребуется собственная авторизация, лицензирование и отдельное хранилище на клиента; текущий Cloudflare прототип предназначен для одного владельца.

## Стоимость и пределы

Workers Paid имеет базовую стоимость $5/месяц и включённые квоты; контейнеры/DO сверх квот оплачиваются отдельно. Выбран `standard-1`, максимум 1 контейнер. Это ограничение параллелизма, а не денежный лимит. Частые/длинные сборы увеличивают стоимость. Контейнер выключается между заданиями; расписание изначально отключено.

## Проверки

Локальные tests проверяют криптохранилище, восстановление alarm jobs, отмену, смену сессии, контроль владельца результата и запрет публикации устаревших попыток. CI также запускает настоящий Chromium с тестовыми API ответами и сборку контейнера. Живая работа Facebook требует отдельного теста владельцем после передачи подключения; успешный CI или `/health` этого не доказывает.
