# JS Control как сервис: доступ после оплаты, бот, плагин, дашборд

Ветка: `claude/saas-access`. Текущая CRM (Apps Script + Google Sheets) и бот владельца не меняются.

## 1. Путь клиента

```
Оплата ──► токен интеграции jsi_… ──► бот: /start jsi_… ──► 3 шага настроек ──► плагин: вход тем же токеном ──► «Подключить соц» ──► дашборд по ссылке + отчёты в боте
```

1. **Оплата.**
   - **На сайте** (карта или крипто): платёжный провайдер присылает подписанный webhook на `POST /billing/webhook`. Платформа создаёт клиента и выдаёт токен интеграции `jsi_…`. Страница успешной оплаты показывает токен и кнопку `t.me/<бот>?start=<токен>`: одно нажатие открывает бота и сразу привязывает чат.
   - **В Telegram** (Telegram Stars): кнопка «Оплатить» прямо в боте. По правилам Telegram цифровые услуги внутри бота продаются только за Stars. Чат привязывается автоматически, токен бот присылает сам.
2. **Бот: базовые настройки.**
   - Шаг 1 — адрес Keitaro (можно пропустить).
   - Шаг 2 — API-ключ Keitaro: проверяется живым запросом и сохраняется зашифрованным. Сообщение с ключом сразу удаляется из чата.
   - Шаг 3 — часовой пояс.
   - Затем бот присылает инструкцию по плагину и ссылку на дашборд.
3. **Плагин.** Клиент входит тем же токеном `jsi_…`. Дальше работает мастер 0.7.0: Ads Manager → «Подключить соц». Сервер собирает данные каждые 15 минут, браузер можно закрыть.
4. **Дашборд.** Секретная ссылка `/d/jsd_…`. Пока данных нет, показывает прогресс подключения. В боте: «📊 Дашборд» выдаёт новую ссылку (старая перестаёт работать), «💳 Подписка» — срок и продление, `/token` — перевыпуск токена.

Токены хранятся только как SHA-256-хэши. Ключи клиентов шифруются AES-256-GCM, ключ шифрования у каждого клиента свой (HKDF от `MASTER_KEY`). Повторный webhook или повторное уведомление об оплате не создают второго клиента. После окончания подписки плагин получает 402, дашборд и бот предлагают продлить.

## 1a. Бесплатный доступ по пригласительным кодам (оплата отложена)

- Владелец (его chat id в `ADMIN_CHAT_IDS`) пишет боту `/invite 30 Вася` и получает код `JS-XXXX-XXXX-XXXX` и ссылку `t.me/<бот>?start=<код>`.
  - Необязательные параметры: число дней (1–365), тариф (`start` / `team` / `agency`, по умолчанию `team`), для кого.
  - Код нужно активировать в течение 14 дней.
- Знакомый открывает ссылку или отправляет код боту. Создаётся **один** аккаунт, бот присылает токен `jsi_…` и запускает мастер настроек.
- Код **одноразовый**:
  - пометка «использован» ставится атомарно, поэтому при одновременной отправке выигрывает только один человек;
  - хранится только хэш кода.
- На один Telegram-аккаунт — один доступ. Если у чата уже есть аккаунт, код не тратится и его можно передать другому.
- `/invites` — список кодов: кому, тариф, статус (ждёт / активирован / отозван / просрочен). `/revoke <номер>` — отозвать неиспользованный код.

## 3. Хватит ли Cloudflare

Коротко: **да, для всего, кроме самой оплаты и публикации плагина в магазине**. Это внешние сервисы при любом хостинге.

| Задача | Чем закрываем в Cloudflare | Статус и риски |
|---|---|---|
| Клиенты, токены, настройки | D1 (до 10 ГБ на базу, 1 ТБ на аккаунт) | ✅ |
| Бот | Worker + webhook | ✅ уже работает для текущего бота |
| Расписание | Cron Triggers (от 1 мин), Durable Object Alarms | ✅ |
| Сбор Facebook | TCP-сокеты из Durable Object + прокси соца; Chromium в Containers как запасной путь | ✅ (раздел 3a). Без прокси запросы идут с IP Cloudflare — прокси соца нужен |
| Изоляция клиентов в сборщике | Durable Object на клиента | ✅ ключ клиента `jsi_` → свой Durable Object, лимит по тарифу |
| Сбор Keitaro | `fetch` из Worker по расписанию | ⚠️ у Workers есть ограничения на порты и прямые IP. Проверить на реальном трекере, запасной вариант — запрос через контейнер |
| История и расчёты (ALL, ROI) | D1 / SQLite в Durable Object (10 ГБ на клиента) | 🔧 перенос логики из Apps Script |
| Дашборд | Worker/Pages + D1 | ✅ веб-дашборд. Копия Google Sheets на клиента возможна через Google API, но упирается в квоты |
| Раздача ZIP плагина и обновлений | Worker / R2 | ✅ |
| Приём оплаты | **нет своего биллинга** | внешний провайдер + webhook, или Telegram Stars |
| Публикация в Chrome Web Store | **не Cloudflare** | раздел 4 |

**Стоимость.** Сбор устроен как у Dolphin, без браузера (раздел 3a).
- Обычный сбор — это HTTP-запросы прямо из Durable Object клиента. Durable Object тарифицируется по времени активности (128 МБ). Прогон соца с несколькими кабинетами — примерно 20–30 секунд, около 3 ГБ·с.
- При обновлении раз в 15 минут это ~2900 прогонов в месяц, порядка **$0.1 в месяц на соц** по тарифу.
- План Workers Paid за $5 включает 400 000 ГБ·с. Этого хватает примерно на **50 соцов с обновлением раз в 15 минут без доплаты**. CPU-время и запись в хранилище — копейки.
- Chromium (`standard-1`, ~$0.004 за запуск) запускается только когда нужно: умер токен или Facebook отверг запрос без браузера.
- Было: Chromium на каждый сбор, ~$10 в месяц на соц.
- Это оценка по прайсу Cloudflare, а не замер. Прокси — расход клиента, как у Dolphin.

## 3a. Схема сбора (по аналогии с Dolphin)

1. **Плагин один раз** передаёт токен, cookies, User-Agent и прокси соца. Как Dolphin x Server.
2. **Каждые 15 минут** Durable Object клиента:
   - через TCP-сокет Cloudflare (`cloudflare:sockets`) открывает туннель через прокси соца (HTTP CONNECT или SOCKS5) и TLS до `graph.facebook.com`;
   - делает те же GET-запросы, что Ads Manager: `access_token` в адресе, cookies и User-Agent профиля.
   - Расходы читаются каждый прогон. Структура (кампании, группы, объявления) — не чаще раза в час.
   - До 4 соцов клиента собираются параллельно.
   - Facebook не обновляет статистику чаще раза в 15 минут — ту же частоту рекомендует Dolphin.
3. **Если токен умер (190/102)** — один запуск Chromium с сохранёнными cookies. Он собирает данные и достаёт со страницы Ads Manager **свежий токен**. Дальше снова дешёвый режим. Переподключать соц не нужно, пока живы cookies: это лучше, чем у Dolphin, где токен обновляют вручную.
4. **Если Facebook отвергает запрос без браузера (код 1)** — сбор этим прогоном идёт через Chromium. После трёх таких раз подряд соц сутки работает через браузер, потом снова пробует дешёвый путь.
5. **Лимит запросов Facebook (4/17/32/613)** — пауза на час. **Ошибка прокси** — браузер не запускается (не поможет), клиент видит, что проблема в прокси.
6. **Изоляция:**
   - ключ владельца `js_srv_` → своё пространство;
   - токен клиента `jsi_` → отдельный Durable Object клиента, с лимитом соцов по тарифу;
   - истёкшая подписка → 402.

   Плагин входит по `jsi_` из бота.

> Главный непроверенный момент: примет ли Facebook запросы токен+cookies с прокси без браузера. Dolphin работает именно так, но живой проверки у нас пока нет. Если не примет, система сама перейдёт на браузер. Это работает, но дороже.

## 3b. Где хранятся данные клиентов и хватит ли объёма

| Что | Где | Объём и лимит |
|---|---|---|
| Клиенты, токены, коды, настройки бота | D1 платформы (общая) | килобайты; лимит 10 ГБ |
| **База клиента**: кабинеты, структура, spend по дням, журнал изменений (названия, статусы, бюджеты), журнал сборов | SQLite в Durable Object **этого клиента** (`cloud-collector/src/archive.mjs`) | ~50–100 МБ в год у команды на 1000 кампаний; лимит 10 ГБ **на каждого клиента**, общего лимита нет |
| Сессии соцов (токены, cookies, прокси) | зашифрованное хранилище того же Durable Object | килобайты на соц |
| **Архив сырых снимков** (gzip, один в час на соц) | R2 `raw/<соц>/<дата>/<час>.json.gz` | ~70 МБ в год на соц; без лимита |

- **Изоляция.** У каждого клиента физически своя база: запрос с токеном клиента попадает только в его Durable Object. Общей таблицы со статистикой разных клиентов нет.
- **Дёшево по записи.** Строка пишется только если значение изменилось. Сбор раз в 15 минут без изменений записывает 2 строки (сводка и журнал прогона), а не перезаписывает снимок. Раньше весь снимок всех соцов переписывался в одном зашифрованном блоке на каждом сборе: при 50 соцах это десятки миллионов записей строк в месяц и упор в лимит 32 МБ.
- **История не удаляется** при отключении соца: удаляются только сессия и сводка.
- **Чтение для дашборда и бота:**
  - `GET /v1/report?since=&until=` — spend по дням и кампаниям с названиями и итогами по валютам;
  - `GET /v1/changes?since=` — что меняли в кампаниях.
- **Стоимость** (прайс Cloudflare, оценка): хранение в Durable Objects $0.20/ГБ·мес, R2 $0.015/ГБ·мес без платы за выдачу. Сто клиентов по 100 МБ — это ~$2/мес за базы. Архив R2 при 500 соцах — ~3 ГБ за квартал, ~$0.05/мес.
- **Срок хранения сырых снимков:** правило жизненного цикла R2 для префикса `raw/`, например 90 дней. Сводная история в базе клиента хранится всегда.
- **Резервные копии:** у SQLite в Durable Objects есть восстановление на момент времени за последние 30 дней. Позже можно добавить выгрузку базы клиента в R2 раз в сутки.

## 3c. Подключение без расширения (как у FBacc)

- Клиент открывает `/bookmarklet` на сервере сборщика и перетаскивает кнопку «JS Control» на панель закладок. Работает в Chrome и антидетектах.
- **В Ads Manager клиент нажимает закладку.** Она читает со страницы ID соца, имя и токен (как FBacc и Dolphin x Server) и открывает `/connect`. Данные передаются в части адреса после `#`: она не уходит на сервер и в логи, а страница сразу её стирает.
- **На `/connect`** клиент вставляет токен из бота (запоминается в этом профиле), прокси соца (`host:port:логин:пароль` или `http://…`, `socks5://…`) и даёт согласие. Сервер проверяет соц запросом через этот прокси, запускает первый сбор и ставит обновление раз в 15 минут.
- **Нечего публиковать и нечего украсть.** Закладка — 2 КБ кода, который только читает токен. Сбор, хранение и расчёты остаются на сервере. Расширение больше не нужно (оно остаётся как запасной вариант).
- **Ограничение.** Закладка не может прочитать HttpOnly-cookies (`xs`). Поэтому:
  - если Facebook примет запросы без них, всё работает как в Dolphin «токен + прокси»;
  - когда токен истечёт, клиент просто снова нажимает закладку, сервер сам восстановить токен не может.
  - Cookies можно вставить вручную, выгрузив их из антидетекта: Dolphin Anty, AdsPower и Octo умеют экспортировать cookies профиля в JSON. Тогда восстановление токена работает автоматически.

: Chrome Web Store или ZIP

**Как у Dolphin.** Dolphin x Server опубликован в Chrome Web Store: умеет искать токены и передавать cookies и прокси в Dolphin. Значит, такой класс расширений в магазин пропускают, но при строгом соблюдении правил.

Требования магазина (с обновлением правил от 01.07.2026, проверки с 01.08.2026):
- **Одна цель:** «подключение рекламного аккаунта Facebook к сервису JS Control». Собирать можно только данные, строго необходимые для этой цели (Limited Use).
- **Политика конфиденциальности** по ссылке и заполненный раздел Privacy practices: какие данные (cookies, токен, User-Agent, прокси), зачем, кому.
- **Явное согласие** перед передачей cookies. Галочка в 0.7.0 уже есть.
- **Минимум прав:**
  - убрать `https://*/*`: адрес сервера фиксированный;
  - `cookies` оставить необязательным;
  - убрать recorder (`webRequest`), если он не нужен клиенту.
- **Никакого удалённого кода**, понятный (не обфусцированный) код.
- **Из магазинной сборки убрать:**
  - запись запросов;
  - импорт токена;
  - кнопку тестовой кампании;
  - демо-ключ;
  - генератор ключа владельца;
  - ручные серверные кнопки.
- Аккаунт разработчика ($5, верификация личности). Публикация **по ссылке (unlisted)**, без поиска. Каждое обновление проходит проверку, от нескольких часов до нескольких дней.
- **Риск:** отказ или снятие из-за передачи сессии, жалобы Meta. Поэтому нужен запасной канал.

**Как у FBacc.** FBacc ставится по гайду с сайта или из Chrome Web Store.
- В обычном Chrome вне магазина можно поставить только через «Загрузить распакованное» в режиме разработчика. На Windows `.crx` вне магазина блокируется, автообновления нет.
- Антидетект-браузеры (Dolphin Anty, AdsPower, Octo), где арбитражники и держат соцы, добавляют расширения в профили из файла или по ссылке магазина. Для них ZIP — нормальный основной путь.
- Нужно: раздача ZIP с платформы (`/plugin`), проверка версии с баннером «Доступно обновление», инструкция для каждого антидетекта.

**Рекомендация:** один код и две сборки.
1. `store` — минимальные права, публикация unlisted в Chrome Web Store.
2. `direct` — ZIP для антидетектов и на случай проблем с магазином.

Обе входят по `jsi_` токену, ключ `js_srv_` клиенту больше не нужен.

## 5. Этапы

1. ✅ **Доступ** (эта ветка): токены, оплата webhook и Stars, мастер в боте, вход плагина, заготовка дашборда.
2. **Сборщик на много клиентов:**
   - Durable Object на клиента;
   - сборщик принимает вход по `jsi_` через service binding с платформой;
   - лимит соцов по тарифу;
   - плагин переходит на `jsi_`.
3. **Расчёты:** перенос логики Dolphin/Keitaro/ALL из Apps Script в Worker + D1, цифры на дашборде, ежедневный отчёт в бот.
4. **Плагин:** сборки `store` и `direct`, политика конфиденциальности, публикация unlisted, баннер обновлений.
5. **Продажи:** лендинг, платёжный провайдер, напоминания о продлении.

## 6. Как развернуть платформу (когда решим)

```sh
cd platform
npx wrangler d1 create js-control-platform        # id → wrangler.jsonc
npx wrangler d1 migrations apply js-control-platform --remote
npx wrangler secret put TELEGRAM_BOT_TOKEN         # НОВЫЙ бот для клиентов
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
npx wrangler secret put BILLING_WEBHOOK_SECRET
npx wrangler secret put MASTER_KEY                 # openssl rand -base64 32; потеря = потеря ключей клиентов
npx wrangler deploy
# setWebhook: url=<PUBLIC_URL>/telegram, secret_token=<TELEGRAM_WEBHOOK_SECRET>
```
